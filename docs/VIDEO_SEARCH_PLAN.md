# 영상 분석·검색 개발계획 (테스트 영상 기준)

기준: 2026-09-30. 사용자가 제공한 `yolo_gemma_elasticsearch_development_plan.md`·`yolo_gemma_architecture_review.pdf`를 현재 저장소에 맞춰 검토한 뒤, **테스트 영상 한 개로 기능을 개발**하기로 한 범위다. 원 계획의 설계 원칙(DB 기준 기록·ES 검색 사본, outbox·버전 검사, 사람별 관찰, present/absent/unknown과 분석 실패 분리, Gemma는 조건 JSON만 생성)은 유지한다.

## 범위와 전제

| 항목 | 결정 |
|---|---|
| 입력 | `../iot-server/assets/test-video.mp4` 하나. 실제 웹캠·IoT 감시는 재개하지 않는다. |

| 정리 | 검증 장치·데이터는 테스트 후 삭제하고 산출물은 Git 제외 `.artifacts/video-analysis/`에 둔다. |

## 테스트 영상 특성

| 항목 | 내용 |
|---|---|
| 형식 | H.264 1280×720, 29.97fps, 84.45초, 약 10MB |
| 내용 | 고정 CCTV가 아닌 편집 홍보 영상. 컷 전환·근접 촬영·자막·마지막 로고(검은 화면) |
| YOLO | 기준 모델 `ppe4-rf27-local-m-20260914`, 클래스 `person, safety_vest, traffic_cone, hard_hat`. 미착용 클래스 없음 |
| 학습 관계 | 영상 출처 `Wle4VAjPWVU` 프레임이 기준 데이터셋에 포함되어 YOLO 정확도가 부풀려진다 |

사람이 프레임을 직접 본 1차 확인(정답표 작성 전 참고)은 다음과 같다.

| 시각 | 장면 | 안전모 |
|---|---|---|
| 14–17초 | 두 사람이 복도를 걸어옴. 한 명은 안전모를 손에 듦 | 두 사람 모두 미착용 |
| 43초 | 두 사람이 바닥 장비 작업 | 왼쪽 착용, 오른쪽 미착용 |
| 47초 | 보안경 근접 촬영 | 판단 불가(머리 일부) |
| 62초 | 두 사람 대화 | 왼쪽 착용, 오른쪽 미착용 |
| 66–77초 | 모니터 앞 착석, 뒷모습 | 미착용 |

조끼는 형광 안전조끼가 아니라 짙은 청색 작업조끼다. 사용자 결정(2026-09-30): **작업조끼도 조끼 착용(present)으로 본다.** 정답표와 Gemma 프롬프트에 이 기준을 쓴다.

따라서 이 영상으로는 **기능 검증(연결·저장·검색·재생·복구)** 만 하고 정확도 수치는 보고하지 않는다. 컷마다 구도가 바뀌므로 작업구역 판정은 첫 버전에서 빼거나 한 컷에만 시험 다각형을 적용한다. 추적 ID가 컷에서 끊기는 것은 정상 동작으로 시험한다.

## P2 결과 (2026-09-30)

- V24 `detection_batches`·`detection_tracks`, `POST /api/iot/detections`(장치 Bearer), `GET /api/detections/tracks`(관리자). 계약·연결 규칙 `ppe-assoc-v1`은 `docs/API.md` 탐지 배치 절.
- 모의 IoT `scripts/simulate-video-iot.py`: 5fps 표본(29.97fps 중 6프레임마다), ByteTrack, HSV 히스토그램 Bhattacharyya 거리 0.35 초과를 컷으로 보고 추적기를 초기화한다. 추적 ID는 `s<장면>-t<번호>`, 배치는 10초 `[start,end)`, batchId는 세션·구간 번호의 UUIDv5라 재전송해도 같다. 네트워크 오류·5xx만 같은 ID로 재시도한다.
- 검증 `.venv/bin/python tests/detections.py`(실제 PostgreSQL, Next.js 8200 경유, 약 40초):
  - 합성 배치: 머리 위 안전모 present, 허리 높이에 든 안전모는 연결하지 않음(미연결 3), 한 프레임만 연결된 안전모는 unknown, 보호구 미탐지는 unknown, 추적 없는 사람 집계, 재전송 duplicate·행 수 불변, 같은 ID 다른 내용 409, 잘못된 토큰 401·다른 장치 403, 구간·정렬·박스·추적·컷 오류 400, 관리자 조회 비로그인 401.
  - 테스트 영상: 컷 26개 감지, 배치 9개 저장·전체 재전송 중복 없음, 저장된 모든 추적이 컷을 넘지 않음, 안전모·조끼 상태는 present/unknown만 존재. 추적기를 초기화하지 않으면(비교용) 10·30·40·50·60초 시작 배치 5개가 `TRACK_SPANS_CUT`으로 거부됐다. 예: 57초 사람의 추적 ID가 컷 뒤 65초 다른 장면에 다시 붙었다.
  - 정답표 초안 대조(정확도 수치 아님): 10–20초에는 present 없음, 41–44초 왼쪽 사람·57–63초 왼쪽 사람 안전모 present(정답표 P2 착용과 일치), 60–63초 오른쪽 사람은 unknown(정답표 P1 미착용 → YOLO로는 absent를 만들지 않음).
- 한계:
  - 10–20초 손에 든 안전모는 YOLO가 아예 탐지하지 않아 "손에 든 안전모 미연결" 규칙은 합성 배치로만 검증했다.
  - 컷 감지는 편집 영상용 단순 기준이다. 26개 중 1.8–2.0초·65.67–65.87초처럼 검은 화면 전후에 연속으로 잡힌 것이 있고, 사람이 컷 목록을 확인하지는 않았다. 고정 CCTV에서는 컷이 거의 없어야 하며 실제 카메라 기준은 미검증이다.
  - 표본 5fps의 짧은 추적(1–2프레임)도 저장한다. 1프레임 추적은 규칙상 항상 unknown이다.
  - 같은 추적이 배치 경계를 넘으면 배치별로 요약이 나뉜다(예: 29.63–29.83초와 30.23–31.63초의 `s9-t1`). 구간 분석(P3)에서 세션·추적 ID로 묶는다.
  - 검증 장치·배치는 종료 시 삭제했다(남은 수 0).
