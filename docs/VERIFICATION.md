## 실제 웹캠 원본 수집 검증 (2026-09-26)

- `iot-jetson-001 / usb-0`의 실제 웹캠 원본 1건을 IoT 로컬 파일과 SQLite outbox에 저장한 뒤 중앙 `POST /api/iot/training-samples`로 전송했다. 로컬 outbox 상태는 `sent`였다.
- 같은 원본과 촬영 시각을 재전송했을 때 HTTP 200과 동일한 중앙 샘플 ID가 반환됐다. 중앙 DB에는 1건만 저장됐고 관리자 샘플 목록·이미지 조회 API도 각각 HTTP 200이었다.
- 검증용 원본 파일과 기록은 양쪽에서 정리했다. IoT 수집 설정은 다시 껐고, IoT API·워커 및 중앙 로컬 개발 서비스도 검증 전 중지 상태로 복원했다.

## Tailscale HTTPS 추가 검증

- HTTPS 9443 → 로컬 Nginx 8200 연결 완료. `tailscale serve status`에서 tailnet only 확인.
- 443 Gradio 및 8443 IoT 연결이 기존과 동일함을 확인.
- 인증서 검증을 유지한 HTTPS 요청으로 로그인 페이지 200 확인.
- HTTPS 로그인·Secure/HttpOnly 세션 쿠키·장치/이벤트 조회·로그아웃/미인증 차단 확인.
- 브라우저 HTTPS 로그인 후 관제 화면 표시 및 JavaScript 예외 없음 확인.
- 검증은 서버 호스트에서 Tailscale 주소로 수행했다. 다른 실제 기기의 접근은 별도 확인하지 않았다.

## 테스트 영상 학습 파이프라인 연결 검증 (2026-09-26)

- 실제 웹캠 대신 `../iot-server/assets/test-video.mp4`에서 프레임 16장을 추출했다. 별도 `verify-video-*` 장치로 중앙 IoT 수신 API에 전송하고, 관리자 API로 다시 읽어 중앙 SHA-256과 일치하는지 확인했다. 같은 manifest를 재전송해 16개 중앙 ID가 그대로 유지됐다.
- 중앙 작업 큐와 Ollama `gemma4:12b`로 16장 분석을 완료했다. SAM3가 같은 중앙 이미지에서 총 30개 후보 박스를 만들었다. 클래스 판단이 다른 프레임 4장을 검토 항목으로 표시했다.
- 박스 미리보기로 16장 중 7장을 선택하고 작은 오탐 박스를 제거했다. 기존 기준 데이터셋의 동일 영상 출처 10장을 검증 분할에서 제외한 뒤 train 2,634장, val 114장, test 82장의 스냅샷을 구성·검증했다.
- 학습 호출 연결 확인용으로 기준 train을 256장으로 제한해 1 epoch를 실행했다. 후보의 독립 test mAP50-95는 0.176으로 기준 모델 0.503보다 낮았다. 이 후보는 현장에 적용하지 않았다. 이후 전체 데이터 3 epoch 시험은 사용자가 목표를 파이프라인 구현으로 좁힌 시점에 중단했다. 전체 학습 완료나 성능 개선을 주장하지 않는다.
- 이 검증은 로컬 Mac MPS 및 기존 `sam3-yolo-pipeline` 가중치·기준 데이터셋으로 수행했다. `review.json`의 사람 검토 뒤 학습을 시작하는 코드 경로를 확인했고, 현장 모델 교체는 범위에 포함하지 않았다.

## 2026-09-27: YOLO·Gemma 데이터셋부터 중앙 배포 API까지

사용자 요청으로 이전 중앙 이미지 3,766장, 자동 처리 작업 3,766건, 관련 검토 기록을 정리했다. 중앙·로컬 이전 테스트 이미지 파일 10,061개를 삭제했다. 기준 프로젝트의 원본 데이터셋·기준 모델·테스트 영상은 보존했다. IoT 감시 일시중지·수집 설정·현장 모델은 변경하지 않았다.

### 실제 검증

- 로컬 테스트 영상 4장만 loopback 중앙에 전송했다. SIM 라우터를 통해 테스트 영상·모델 파일을 전송하지 않았다.
- Gemma 자동 분석 4장 완료. YOLO+Gemma 선별 2장 포함, 2장 제외(저신뢰·클래스 불일치).
- 관리자 API → PostgreSQL 작업 큐 → Python 워커로 데이터셋 구성, 1 epoch 학습, 독립 test 평가까지 완료했다.
- 큐 학습의 기준 mAP50–95 0.5026001, 후보 0.4994752, 차이 -0.0031249. 승격 기준 미달이며 실제 후보 등록 API가 409로 차단했다. 성능 개선을 주장하지 않는다.
- 별도 CLI 축소 검증은 기준 train 8장 + 선별 2장, val 114장, test 82장, 동일 테스트 영상 10장 제외로 1 epoch를 완료했다. 이 축소 실행의 평가 차이는 0이었다.
- 실제 PostgreSQL에 V9·V10 migration 적용. 학습 API의 미인증, CSRF 누락, 중복 샘플, 입력 범위, 동시 활성 작업, 잘못된 단계 전이를 확인했다.
- 만료 임대의 완료 보고 거부, 작업·실행 실패 기록을 실제 DB/API로 검증했다. 관리자 목록은 전체 이미지 분석 스냅샷을 제외한다.
- 임시 장치 두 개와 작은 가짜 파일로 배포 계약을 검증했다. 평가 제한·파일 해시·다른 장치 차단·동시 배포 차단·순차 상태 전이·동일 상태 재전송·활성 해시 검사·완료 후 다운로드 차단·파일 변조 차단이 통과했다. 이 테스트는 실제 모델 적용 시험이 아니다.
- 기존 인증·장치 분리·이벤트 중복/동시성·검색 통합 테스트 4개, CLI/선별·모델 변경 차단 단위 테스트 8개 통과.
- Java 컴파일, TypeScript 타입 검사, Python 문법 검사, `git diff --check` 통과.
- agent-browser로 데이터셋·학습·배포 화면을 확인했다. 완료 상태·선별 수·평가 미달·후보 없는 배포 버튼 비활성화가 표시되고 브라우저 오류가 없었다.

### 검증 후 정리

이번 중앙 테스트 이미지 4장·검증 장치·작업·임시 학습 실행·임시 배포 요청을 삭제했다. 새 로컬 테스트 이미지 3,124개도 정리했다. 최종 확인: 중앙 samples 0, labeling_jobs 0, annotation_reviews 0, training_runs 0, model_deployments 0, 중앙 media JPEG 0. 평가 수치·로그·후보 가중치는 Git 제외 로컬 산출물로 보존하되 진행 기록을 비활성화해 현재 화면에는 표시하지 않는다.

실제 IoT 모델 전송·적용·서비스 재시작·웹캠 재개는 수행하지 않았다. 중지된 Docker 볼륨은 시작·삭제하지 않았으므로 그 물리 정리 완료를 뜻하지 않는다.

### IoT 협업 완료 보고

원격 IoT 채팅의 최종 보고: 명시적 CLI 모델 배포 클라이언트·모델/메타데이터 로더·중단 복구를 구현하고 전체 단위 테스트 55개, 문법·diff 검사를 통과했다. 실제 모델 다운로드·Jetson GPU 검증·현장 적용은 하지 않았다. 기존 API·워커 서비스, 감시 일시중지, 수집 설정을 보존했으며 신규 코드는 실행 서비스에 아직 반영하지 않았다. [연동 문서](IOT_CENTRAL_HANDOFF.md)의 최신 절을 따른다.

### 중단 후 재개: 중앙 배포 실패·롤백 계약 검증

- `python3 tests/deployments.py`를 실행 중인 중앙 API·실제 PostgreSQL에서 재검증했다.
- IoT 미인증 401과 관리자 배포 요청의 CSRF 누락 403을 확인했다.
- PENDING·DOWNLOADING·VALIDATING·APPLYING 각각에서 FAILED 보고, APPLYING에서 ROLLED_BACK 보고와 이전 활성 해시 저장을 확인했다.
- 종료 보고 재전송은 성공하며, 다른 활성 해시 재보고·종료 후 단계 재진입·모델 다운로드는 409로 차단했다. 종료 배포는 desired에 나타나지 않는다.
- 임시 장치·가짜 파일만 사용했고 해당 테스트 자료는 `finally`에서 정리했다. 실제 모델 적용·서비스 재시작·운영 설정 변경은 수행하지 않았다.
- `git diff --check` 통과.

### 중단 후 재개: 실제 IoT와 중앙 재전송 검증

- 원격 IoT가 검증 전용 장치로 실제 중앙 HTTPS API에 접속했다. 별도 프록시에서 503과 응답 유실을 만들었으며 운영 중앙 서버를 중단하지 않았다.
- START/END 전송 후 응답 유실 재시도에서 `duplicate:true`를 확인했다. 중앙 DB에서도 각 유형 1건씩만 저장됐다.
- 기존 테스트 영상 이미지 1장을 재전송해 같은 중앙 샘플 ID로 수렴했다. 중앙 DB에서 이미지 1건·LABELED와 자동 작업 1건·COMPLETED를 확인했다.
- 작은 가짜 후보 파일로 desired·다운로드·SHA-256·상태 보고를 검증했다. 배포는 FAILED로 종료했고 종료 후 다운로드는 409였다. 실제 모델 로드·GPU 추론·적용 검증을 뜻하지 않는다.
- 중앙의 해당 검증 장치·이벤트·이미지 파일·자동 작업·배포·후보·실행·가짜 파일·임시 토큰 파일을 정리하고 관련 DB 잔여 0건을 확인했다. 다른 장치의 자료는 보존했다.
- 중앙 `tests/integration.py`의 인증·CSRF·장치 분리·이벤트 동시 중복·검색 테스트 4개도 통과했다.
