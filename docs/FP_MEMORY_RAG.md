# 오탐 판단 기억: Gemma + pgvector RAG (2026-10-09)

## 목적

현장 YOLO가 일반 옷을 안전조끼로, 대머리를 안전모로 잡는 오탐을 Gemma가 다시 확인해 왔다(`fp-v4`). 그런데 Gemma는 글 설명과 고정 예시만으로는 현장 남색 작업 조끼를 "점퍼"로 보고 오탐으로 확정했다. 사람이 한 번 판단한 사례를 기억해 두고, 새 박스가 그 사례와 비슷하면 사람의 판단을 근거로 쓰는 것이 이 기능의 목표다. 관리자가 시연에서 10장 정도만 판단해도 효과가 나야 한다.

## 구성

| 단계 | 담당 | 내용 |
|---|---|---|
| 사례 저장 | 중앙(Spring Boot·PostgreSQL) | `fp_memory`(V37): 클래스·판단(real·false)·출처(CLAUDE·ADMIN)·512차원 `vector`·확대 사진. pgvector 0.8.7, HNSW 코사인 색인 |
| 기본 사례 | `scripts/seed-fp-memory.py` | Claude가 10/07·10/08 웹캠 사진을 직접 판별한 88건(안전모 오탐 13·조끼 오탐 52·조끼 정탐 23) |
| 관리자 사례 | 오탐 확인 창 → 승인 | 승인 순간 보호구 박스마다 기억 행 생성(뺀 박스 false, 남긴 박스 real), observer가 다음 반복에서 임베딩 |
| 임베딩 | `ai-worker/fp_memory.py` | open_clip ViT-B-16(laion2b_s34b_b88k). Gemma가 보는 확대 영역과 같은 영역 |
| 검색 | 중앙 `POST /internal/ai/fp-memory/search` | 같은 클래스에서 정탐·오탐 판단마다 가장 비슷한 사례를 따로 찾는다(한쪽 사례가 많아도 반대 사례가 빠지지 않게) |
| 판정 | `ai-worker/fp_check.py` `fp-v5` | ① 정탐·오탐 최고 유사도 차이 0.03 이상 → 사람 판단을 따름(Gemma 호출 없음) ② 애매하면 비슷한 사례 사진을 예시로 붙여 Gemma 판정(RAG) ③ 기억이 없으면 고정 예시 |
| 화면 | `/video-search` 오탐 확인 | 판정 근거(판단 기억·Gemma+유사 사례·Gemma), 근거 사례 사진·유사도, 승인 시 기억 추가 안내 |

기억 판정만으로는 데이터셋에 넣지 않는다. 학습 데이터(`local:admin-fp`)는 지금처럼 관리자 승인으로만 쌓인다.

## 성과 측정

- 평가 사진: 10/08 16:35 이후 `iot-jetson-001 / usb-0` 장치 원본 사진(오버레이 없음)에서 현장 모델 eb08d194가 신뢰도 0.4로 잡은 조끼 박스 26개. 베이지 반팔 셔츠 오탐 15개, 남색 작업 조끼 정탐 11개. 정답은 Claude가 사진으로 확인했다.
- 기본 사례 88건은 같은 날 15:30 이전 사진과 10/07 사진이라 평가 사진과 시간이 겹치지 않는다.
- 작업 파일: `.artifacts/rag-exp-20261009/`(Git 제외. `items.json`·`gemma_v4.json`·`rag_v5_claude.json`·`results.json`).

| 판정 | 전체 정답 | 베이지 셔츠(오탐) | 남색 조끼(정탐) | 실제 조끼를 오탐으로 확정 | 박스당 시간(중앙값) |
|---|---|---|---|---|---|
| 이전 `fp-v4` Gemma 단독(고정 예시) | 15/26 | 15/15 | 0/11 | 11 | 10.7초 |
| 이후 `fp-v5` 판단 기억 + RAG | 26/26 | 15/15 | 11/11 | 0 | 0.03초 |

- `fp-v5`의 26건 중 25건은 판단 기억으로 바로 결정했고, 1건(유사도 차이가 0.03 미만)은 비슷한 사례를 붙인 Gemma가 "남색 작업 조끼"로 맞게 판정했다. 같은 사진을 `fp-v4`는 "남색 점퍼"로 보고 오탐으로 확정했다.
- 관리자 10장만 있는 경우(오프라인 모의, 같은 임베딩·결정 규칙): 평가 사진에서 정탐 5·오탐 5를 무작위로 골라 기억으로 두고 나머지 16건을 판정하기를 200회 반복했다. 평균 15.3건을 결정했고 그중 평균 14.9건이 맞았다(결정한 것의 오답률 약 2.8%). 시간순으로 처음 나온 정탐 5·오탐 5를 쓰면 16건 모두 결정·정답이었다.
- 실제 흐름 검증(테스트 백엔드): 검증 장치가 원본 사진을 보내자 `fp-v5`가 베이지 셔츠를 기억으로 오탐 판정(유사도 0.92)·관리자 확인 대기로, 남색 조끼를 기억으로 정탐(확인 불필요)으로 처리했다. 브라우저에서 승인하자 관리자 기억이 생기고 워커가 임베딩을 채웠다.

## 한계

- 평가 사진은 기본 사례와 같은 장소·같은 사람들·같은 옷이다. 반복되는 현장 오탐에는 효과가 크지만, 처음 보는 사람·옷에서는 유사도 차이가 작아 Gemma(RAG)로 넘어가는 비율이 늘어날 것이다. 다른 장소 사진으로는 측정하지 않았다.
- 평가 26건은 조끼만이다. 안전모 오탐(대머리) 평가 사진은 이번 평가 구간에 없었다.
- 결정 기준(차이 0.03, 한쪽 사례만 있을 때 0.9)은 이 평가 사진으로 정했다. 사례가 쌓이면 다시 확인해야 한다.
- 관리자가 잘못 판단하면 그 판단이 비슷한 박스에 그대로 퍼진다. 판정 근거에 사례 사진과 출처를 보여 주는 이유다. 잘못된 기억을 지우는 화면은 아직 없다.
- 사례가 수백 건 이하라 색인 없이도 빠르다. pgvector 색인은 사례가 많아질 때를 위한 것이며 대규모 성능은 측정하지 않았다.
- Docker 구성은 `pgvector/pgvector:0.8.7-pg17` 이미지로 바꿨지만 실행 검증하지 않았다(기존 alpine 볼륨 호환 미확인).
