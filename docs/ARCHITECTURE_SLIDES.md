```text
 │                          │                         │   🤖 AI 워커 ── 🦙 Ollama gemma4    │

 └──────────────────────────┘                         └─────────────────────────────────────┘
                                                                     │
                                                                     ▼

```

**핵심 원칙**

| | 원칙 |
|---|---|
| ➡️ | IoT가 중앙에 요청하고 중앙은 응답만 한다. 중앙이 IoT로 직접 접속하지 않는다. |
| 🔒 | 모든 통신은 Tailscale 사설망 안에서만 이뤄진다. Funnel 공개 없음. |
| 🧩 | Spring Boot는 추론·학습을 실행하지 않는다. AI 작업은 호스트 Python 워커가 맡는다. |

## 4️⃣ IoT 서버 내부 구성

```text
   🎥 USB 웹캠 (usb-0)
        │ 프레임
   ┌────▼──────────────┐
   │ 🧠 추론 워커       │  YOLO 사람·PPE 검출
   │  worker/main.py   │  라바콘 영역 침입 판별
   └────┬──────────┬───┘
        │ 보고     │ 오버레이 H.264
   ┌────▼───────┐  └──────────────▶ 📡 중앙 MediaMTX (RTMP)
   │ 🐍 로컬 API │  app/main.py :8100
   │  상태·설정  │  현장 화면·영역 설정
   └────┬───────┘
   ┌────▼───────┐
   │ 📦 SQLite  │  설정·영역·이벤트, 중앙 전송 outbox
   └────┬───────┘
        │ 🔐 장치 Bearer 토큰
        ▼
   ☁️ 중앙 /api/iot/**
```

| 아이콘 | 기능 | 상태 |
|:---:|---|---|
| 🧠 | YOLO 추론·침입 판별 | ✅ 구현 |
| 📡 | 오버레이 영상 송출(WebRTC 재생 확인) | ✅ 구현 |
| 💓 | 등록·5초 heartbeat·카메라 상태 | ✅ 구현 |
| 🔁 | 이벤트·이미지 outbox 재전송 | ✅ 503·응답 유실 재전송 검증 |
| 🚀 | heartbeat 응답 배포 자동 적용 | ⚠️ IoT 커밋 있음, 실제 연동 일부 미검증 |
| 🩺 | 재시작·로그 요청 처리 | ⚠️ 커밋됨, 운영 미반영 |
| 🎯 | 감지 기반 탐지(`/api/iot/detections`) 송신 | ⏳ 모의 IoT만, 실제 송신 미구현 |

## 5️⃣ IoT ↔ 중앙 API 계약

| 아이콘 | API | 방향 | 내용 |
|:---:|---|:---:|---|
| 🪪 | `POST /api/iot/register` | IoT → 중앙 | 사전 발급 장치 등록·정보 갱신 |
| 💓 | `POST /api/iot/heartbeat` | IoT → 중앙 | 5초 주기 실행 상태·모델명·해시·오류 |
| ↩️ | heartbeat 응답 | 중앙 → IoT | `deployment`·`monitoring`·`restart`·`logRequest` |
| 🚨 | `POST /api/iot/events` | IoT → 중앙 | 침입 시작·종료 (UUID로 중복 방지) |
| 🖼️ | `POST /api/iot/training-samples` | IoT → 중앙 | 수집 이미지 |
| 🎯 | `POST /api/iot/detections` | IoT → 중앙 | 추적 단위 탐지 배치 |
| 📜 | `POST /api/iot/logs` | IoT → 중앙 | 요청받은 서버 로그 |
| 📡 | RTMP `:1935` | IoT → 중앙 | 오버레이 실시간 영상 |

> 💡 중앙 → IoT 명령은 모두 **heartbeat 응답에 실어** 전달한다. 방화벽·NAT 뒤 장치도 별도 포트 개방 없이 동작한다.

## 6️⃣ 인증 경계

| 아이콘 | 호출자 | 방식 |
|:---:|---|---|
| 👤 | 관리자 `/api/**` | 서버 세션 + HttpOnly 쿠키 + CSRF, BCrypt 비밀번호, 미인증 401 JSON |
| 📹 | IoT `/api/iot/**` | 장치별 Bearer, DB에는 SHA-256 해시, 토큰 장치 ID = 요청 장치 ID |
| 🤖 | 워커 `/internal/ai/**` | 별도 워커 Bearer, loopback 전용 |
| 📺 | MediaMTX `/internal/media/auth` | publish = 장치 토큰+경로, read = 5분 난수 토큰+정확한 경로 |

```text

 IoT 이미지     ──▶   Gemma4 설명·태그  ──▶  YOLO 박스 초안  ──▶  YOLO 이어학습   ──▶  후보 등록
```

## 🔟 데이터 흐름 ④ 영상 분석·검색

```text
 🎞️ 녹화 영상 ──▶ 🎯 탐지 트랙 ──▶ 🔍 구간 분석(Gemma) ──▶ 🐘 PostgreSQL
                                                              │
 👤 "어제 오후 사람 나온 장면?" ──▶ 🦙 질문 → 조건 JSON ──▶ SQL 검색 ──▶ ▶️ 해당 시각 재생
```

- Gemma는 **판정·조건 생성만**, 기간 계산·검색은 코드와 PostgreSQL이 한다.
- 테스트 영상 한 개로 한 바퀴 구현. Elasticsearch·실제 IoT 송신은 ⏳ 미구현.
